### 待决：材料总量（R6 前正式决定）

现状：搜集点与工具车每天天亮补货，跨天累计无上限，「材料只够一条线」无法成立。倾向方案：**搜集点不补货，或设全图固定总量上限**。

若改为「不补货（每点整局一次）」，对现有点位的影响：

| 影响 | 说明 |
|------|------|
| 全图总量 | 木料 5、绳索 3、金属 5（含工具间 3、工具车 1）、套件各 1。两线都不用套件需金属 6 → 不够双线 ✔；但**用套件时两线只需 木1 绳1 金属2**，仍够双线 → 还需限制套件（如全图只放 1 个套件、或套件只顶 1 档） |
| 才能错配永久损失 | 现在是「搜一次就空」：没对应才能的动物去搜，只拿 1（少拿的永久没了）。不补货后这是一次性惩罚；可改成「按剩余库存扣」而非整点清空 |
| 绳索偏紧 | 全图绳 3，正好等于攀爬线不用套件的需求；晾衣架无攀爬只拿 1 → 无猴时绳最多 2 |

## 已锁定数值 / 规则（摘）

- Hard（允许时）：时间 ×3、噪音 ×2、痕迹 ×2；**不**直接 Alert+1  
- 同一痕迹 Alert 增量**只结算一次**（`settled` / 等价状态 + 测试）  
- Alert3 施工噪音倍率起点 **×1.3**（`AlertParams`）  
- Alert4 UI：「再升一档将全园搜查」；Alert5 中止施工须明确原因  
- 叫嚷：每日 4 + 冷却；用尽「嗓子哑了」；不计 Alert  
- 投掷：键 T、冷却 8s、无材料消耗（石子表现）；`CapabilityIds.THROW`  
- 痕迹：跨天保留至被发现；天亮衰减 **50%**（比例入 Params）  
- 无员工在场时，任何噪音**不得**使 Alert 上升（`p2_action_cost` / `p2_alert_tiers` 断言）  
- 背包：**浣熊容量 4 / 猴子 2**；重物（仅套件，`ItemDef.heavy`）：移速 −40%、禁用攀爬  
- 测试：`p2_full_loop` 改预算断言（3–5 天正解线；材料不够双线；无料拒最后一档）
